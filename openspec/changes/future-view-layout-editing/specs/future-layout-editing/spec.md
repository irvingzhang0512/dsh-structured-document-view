# F009 更多布局与内容编辑

## Purpose

为 dsh-structured-document-view 的更多布局与内容编辑维护唯一可编辑的行为与验收规格，保留原编号 F009，区分当前预期、尚未实现设计和历史验证；原始需求、项目资料及旧文档继续原位只读保留。

## ADDED Requirements

### Requirement: F009 更多布局与内容编辑

系统 SHALL 按下列完整场景落实更多布局与内容编辑的预期、边界与验收。本节为原有待实现设计的格式迁移，尚未获得实施批准，不作为现有能力。

#### Scenario: F009-S01 历史场景

- **WHEN** 用户讨论新增布局或拖动内容编辑
- **THEN** 历史场景：原始需求中的扩展布局及拖动修改文档等设计未作为当前能力交付；现行架构将导图定义为只读。

#### Scenario: F009-S02 边界与异常

- **WHEN** 用户讨论新增布局或拖动内容编辑
- **THEN** 边界与异常：仅保留历史规划来源，不代表已承诺本次开发；尚无对应完整运行实现。

#### Scenario: F009-S03 验收条件

- **WHEN** 用户讨论新增布局或拖动内容编辑
- **THEN** 验收条件：重新讨论内容编辑的内核事务、权限和布局支持后再实施；当前不能启用拖动编辑。

#### Scenario: F009-S04 原始后续视图候选

- **WHEN** 重新审阅原始需求第 2、21、22 章的未来范围
- **THEN** 分别保留流程图、PPT 大纲、时间线、看板及其他结构化视图的候选意图，不把现有 mind／logical／down 当作这些视图已经交付；PPT 大纲也不等于 PPT 编辑。多人协作、复杂视觉主题／动画、视图内大量正文编辑、AI 自动选择最佳视图及大文档增量渲染均未承诺本次实施，须先补齐具体验收再确认。

#### Scenario: F009-S05 拖动视觉位置与文档父子关系

- **WHEN** 讨论原始第 9.3 章的拖动节点能力
- **THEN** 必须区分只改视觉位置与改变文档父子结构：前者只写 View State，后者须调用文档内核 move_node 并遵守事务、版本、权限与错误边界；IR 继续是内容真源。此行为是未落地设计，不能在现有只读导图启用编辑或认为图形库状态已修改文档。
